# Gemara — Reading and Writing Protocol

**Purpose:** preserve WHY, WHY-NOT, uncertainty, evidence, decisions, failed alternatives, consequences and conditions for reopening, so a fresh agent can continue without relying on chat memory.

## Read
1. Locate the relevant record and linked prior reasoning.
2. Read the full material body before relying on a summary.
3. Surface material objections, rejected paths, unresolved questions and required prior decisions.
4. Distinguish current authority from historical, superseded or experimental claims.
5. Check actual code, provider state, Jira and evidence before treating an assertion as true.

## Write
Write only when reasoning materially changes. Include premise, gap, evidence, interpretation, objection/WHY-NOT, result, bounded conclusion, action, unresolved and reopen-if where relevant. Link sources and prior records.

## Correct
Never silently rewrite history. Create a correction or continuation that explicitly links the prior record, explains what changed, and preserves rejected reasoning.

## Review
Prefer PR review. No self-asserted PASS without verification. A file existing in Git does not prove that an external action happened.
